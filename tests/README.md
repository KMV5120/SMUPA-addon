# 端到端集成测试（平台侧单侧）

`e2e_verify.py` —— 把「同学侧」和「值班员侧」串成一条完整业务链路的集成测试，
由交付方随包提供，供管理员验收时复跑。

---

## 它验的是什么

**不是**逐个接口返回 200，而是**跨侧一致性**。两个模拟用户：

```
① 同学（匿名，同学侧预约页 / 小程序）
     看须知 → 选座 → 提交预约 → 查我的预约 →（事后）自助取消 / 改约
② 值班员（平台登录态）
     看到新单 → 通过验证 → 受理 → 签到 → 签退 → 发满意度调查 → 分享码 → 统计
```

关键断言举例：

- 同学提交后，值班员平台的**列表页里真的能看到这张单**
- 值班员签退后，**座位真的被释放**、同学侧查到的状态真的变成「已完成」
- 操作流水 / 统计计数 / 分享码 / 问卷数据这些副产物**都对得上**
- 冥想室的整条链路**不污染**平台原有心理预约的数据表

共 **16 组、177 条断言**，其中：

| 组 | 覆盖 |
| --- | --- |
| [1]–[7] | 对外接口契约 → 提交 → 值班员受理链路 → 状态回流 |
| [8] | 满意度调查闭环（含匿名公开页、数据接口的开与关） |
| [9] | 操作流水 / 统计 / 分享码 / 打印 |
| [10] | 同学自助取消与改约（含归属校验负例） |
| [11]–[12] | 权限门槛、模块隔离 |
| **[13]** | **咨询预约栅格周历**（本次随包交付的平台侧改动）与首页区块 |
| **[14]** | **CSRF**：详情页动作在真实浏览器里点得动吗（见下） |
| **[15]** | **未验证单的查看门槛** —— 用 3/4 挡、5 放行把 `>=5` 卡死 |
| **[16]** | **静态资源可达性** —— 新增 CSS 漏了页面会裸奔 |

### ⚠️ 第 [14] 组为什么必须存在

Django 测试客户端**默认 `enforce_csrf_checks=False`** —— 整个 CSRF 校验被绕过。
后果是：即使模板里漏了 `{% csrf_token %}`（**真实浏览器里所有处理按钮都会 403**），
前面 13 组也会**全绿**。

这个坑真实发生过：`detail_meditation.html` 一度 **11 个 form 一个 token 都没有**
（对照：咨询预约的 `detail_reservation.html` 每个 form 都有），
而 155 项自检全部通过 —— 属于照搬咨询预约时的遗漏。

所以第 [14] 组显式用 `Client(enforce_csrf_checks=True)` 再走一遍，
并额外做**模板级兜底**：逐个检查每个 `<form>` 后面是否跟了 `{% csrf_token %}`，
防止以后新增表单时又漏。**回归价值：人为移除 token 后该组会报 5 条失败。**

## 怎么跑

必须在一个**能 import 到平台代码**的 Python 环境里跑（它不是独立的测试工程）：

```bash
cd <平台根目录>          # 有 manage.py 的那层
python ../tests/e2e_verify.py
```

退出码 0 = 全过；非 0 = 有失败项，输出里会逐条打印期望值与实际值。

### 跑之前要改两处

| 位置 | 改什么 |
| --- | --- |
| 文件顶部 `os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'local_settings')` | 改成你们的 settings 模块名 |
| 常量 `CHAIR_CODE` | 一个有发调查邀请权限的主席账号（`user_type >= 4`） |
| 常量 `STAFF_CODE` | 一个低权限账号（干事，`user_type = 1`），用于验证权限门槛 |
| 常量 `MINISTER_CODE` | 一个**部长**账号（`user_type = 3`），用于把未验证单门槛卡死 |
| 常量 `ASSIST_CODE` | 一个**主席助理**账号（`user_type = 5`），门槛的临界值 |

后两个常量只服务第 `[15]` 组。**它们不是可有可无的** —— 只拿"干事 vs 主席助理"
去对比是卡不住精确门槛的：门槛被误改成 3 时，干事照样被挡，测试不会报警。
用 3（挡）、4（挡）、5（放行）三点夹逼，才能证明门槛**就是 5**。

> 第 `[15]` 组还会临时造一个 `user_type=4`（督导组）账号 ——
> 种子里通常没有这个职务，就地创建、随事务回滚，用完即消。
> 若你们的库里已有督导组账号，也可以改成直接用它。

### 数据安全

所有写入**整体包在一个事务里，最后回滚**，不会在库里留下测试数据。
可以反复运行。

## 两处测试替身（不是绕过，是刻意的）

1. **`send_email` 用桩替换**
   平台发信用的是裸 `smtplib`（`utils/SMTP.py`），**不受 Django `EMAIL_BACKEND` 控制**，
   所以本地/CI 里真发必然失败。测试里换成桩，并**断言信件内容**
   （收件人 / 主题 / 正文 / 评价链接）——这比让它真发失败更有信息量。

2. **`SURVEY_API_KEY` 走 `override_settings`**
   先断言「未配置时拒绝访问」，再临时配置后断言数据能取出，覆盖开关的两个方向。

## 已知的既有行为（测试里固化成断言，避免以后被误当成新 bug）

- **`/calendar/`（平台原有的咨询预约周历）遇到 status=1 且时间格式坏的单，
  会整页替换成错误页**（HTTP 仍是 200，但周历完全看不到）。
  这是既有行为，本次交付**没有改动它**；新增的 `/consultation/calendar/` 则会
  跳过坏数据继续渲染并在页首提示。两组断言都在 [13] 里。

- **问卷数据对外接口 `/meditation/api/survey/data/<key>/` 的路由是 `(?P<key>\w+)`**，
  `\w` 不含连字符 —— 所以 `SURVEY_API_KEY` 里**不能有 `-`**，否则会 404
  （不是 401，是路由直接匹配不上）。这与平台原有心理预约的同名路由是同款写法，
  属继承的既有约定。
